## Require the package

```bash
composer require nowo-tech/currency-kit-bundle
# optional
composer require symfony/scheduler dragonmantank/cron-expression   # scheduled sync
```

## Register the bundles

With Flex the bundles are registered from their `type: symfony-bundle`. Without Flex, in `config/bundles.php`:

```php
return [
    // …
    Nowo\OutboundUrlGuardBundle\NowoOutboundUrlGuardBundle::class => ['all' => true],
    Nowo\CurrencyKitBundle\NowoCurrencyKitBundle::class          => ['all' => true],
];
```

No configuration is needed for the defaults (ECB source, default entity manager's connection, `nowo_` table prefix).
See [CONFIGURATION.md](CONFIGURATION.md).

## Supported databases

MySQL 8.4, MariaDB 11.4 and PostgreSQL 16 (tested in CI). SQLite is for development and tests only: it keeps
`DECIMAL(24,12)` as a double, so it cannot hold every rate at full precision.

## Create the tables

The bundle maps its five tables read-only on the configured entity manager, so Doctrine's schema tools see them:

```bash
bin/console doctrine:migrations:diff        # hosts with migrations: review and run the generated migration
bin/console doctrine:schema:update --dump-sql   # a drift gate shows no diff once the tables exist
bin/console nowo:currency-kit:schema-check  # columns, collations and indexes of the live tables
```

The bundle ships no migrations (house style). The reference DDL per platform is in
[UPGRADING.md](UPGRADING.md#010) (generated by the test suite from the mapping); `bin/console
nowo:currency-kit:schema-check --ddl` prints it for your platform and prefix.

## First sync

```bash
bin/console nowo:currency-kit:rates:sync          # loads the last 90 days on the first run
bin/console nowo:currency-kit:rates:show --currency=USD
bin/console nowo:currency-kit:convert 100 USD EUR
```

Then keep the rates current with the Scheduler bridge or cron ([USAGE.md](USAGE.md#keeping-rates-current)).
